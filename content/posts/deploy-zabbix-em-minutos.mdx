Neste artigo o deploy do Zabbix leva menos de dois minutos. Aproveitando a estrutura, vamos monitorar um DVR Intelbras via SNMP — tudo em cerca de 15 minutos.

<Callout type="info" title="Qual versão do Zabbix?">
Este guia usa a linha **7.0 LTS**, com suporte de longo prazo; a 7.4 é a versão *standard* mais recente e a próxima LTS (8.0) segue o calendário oficial de ciclo de vida<Cite id="zabbix-lifecycle" />. Em produção, prefira sempre uma versão LTS.
</Callout>

## Requisitos para este laboratório

- **RAM**: 4 GB (o PostgreSQL e o servidor Zabbix são os maiores consumidores)
- **CPU**: 2 vCPUs
- **Docker Engine** recente com o plugin **Docker Compose v2** (`docker compose`, sem hífen)
- **SO**: Linux (Debian, Ubuntu, RHEL e derivados)

## Deploy em 1 minuto

<Video src="/videos/docker/deploy-zabbix/single_line_deploy_zabbix.mp4" title="Deploy do Zabbix com um único comando" caption="Gravação do deploy completo com o script do repositório." />

```bash
git clone https://github.com/leonardoSaaads/zabbix-docker
cd zabbix-docker
less install.sh        # leia antes de executar!
sudo bash install.sh
```

<Callout type="security" title="Revise scripts antes de executá-los com sudo">
Mesmo sendo um projeto meu, a regra vale sempre: leia o código, verifique o repositório e o histórico de commits antes de rodar qualquer coisa como root<Cite id="zabbix-docker-repo" />.
</Callout>

### O que o install.sh faz

1. Verifica as dependências (Docker e Docker Compose).
2. Gera o arquivo `.env` com as configurações.
3. Cria os volumes de persistência.
4. Executa `docker compose up -d` e aguarda os serviços ficarem prontos.

```text
zabbix-docker/
├── docker-compose.yml
├── .env.example
├── install.sh
├── volumes/
└── README.md
```

Os componentes seguem a arquitetura oficial em containers: servidor, frontend web, banco de dados e agente, cada um em sua imagem<Cite id="zabbix-containers" />.

## Acesso ao Zabbix

Após o deploy, acesse `http://localhost:8080` (porta definida no compose do projeto).

### 1. Baixe o template

No [catálogo de integrações do Zabbix](https://www.zabbix.com/br/integrations/intelbras), baixe o template compatível com a sua versão<Cite id="zabbix-intelbras" />.

<Figure src="/images/zabbix/zabbix-intelbras.png" alt="Página de integrações Intelbras no site do Zabbix" maxWidth={640} />

### 2. Habilite o SNMP no DVR

Na interface web do DVR, em **Configuração → Rede → SNMP**:

- **Prefira SNMPv3** com nível *authPriv* (autenticação SHA-256 e criptografia AES), se o firmware suportar<Cite id="rfc3414" />.
- Se só houver SNMPv2c, **troque a community `public`** por um valor aleatório: no v2c, ela trafega em texto claro e funciona como senha<Cite id="rfc1901" />.
- Restrinja o acesso SNMP ao IP do servidor Zabbix e mantenha o DVR em uma VLAN de gerência.

### 3. Teste a conectividade

<Tabs labels={["Debian/Ubuntu", "RHEL/Fedora"]}>
<Tab>

```bash
sudo apt update && sudo apt install -y snmp
```

</Tab>
<Tab>

```bash
sudo dnf install -y net-snmp-utils
```

</Tab>
</Tabs>

```bash
# SNMPv3 (recomendado)
snmpwalk -v3 -l authPriv -u zabbix -a SHA-256 -A 'SENHA_AUTH' -x AES -X 'SENHA_PRIV' <IP_DO_DVR> system

# SNMPv2c (legado)
snmpwalk -v2c -c 'COMMUNITY_FORTE' <IP_DO_DVR> system
```

A saída deve listar `sysDescr`, `sysUpTime`, `sysName` etc.<Cite id="mauro-snmp" />

### 4. Importe o template

Em **Coleta de dados → Modelos** (*Data collection → Templates*), clique em **Importar**, selecione o arquivo, mantenha marcadas as opções de criar e atualizar e confirme.

### 5. Crie o host do DVR

Em **Coleta de dados → Hosts**, clique em **Criar host**:

- **Nome do host**: `DVR_Intelbras` · **Grupo**: por exemplo, "Dispositivos de segurança".
- **Interface**: tipo **SNMP**, IP do DVR, porta `161`, versão conforme o passo 2.
- **Templates**: o template Intelbras importado.
- **Macros**: para v2c, `{$SNMP_COMMUNITY}` com a community configurada (como macro **secreta**). Para v3, preencha usuário, protocolos e frases-senha na própria interface SNMP<Cite id="zabbix-snmp" />.

### 6. Verifique e visualize

Aguarde alguns minutos pela primeira coleta. O ícone de disponibilidade **SNMP** do host deve ficar verde. Em **Monitoramento → Dados recentes**, filtre pelo host para ver temperatura, discos e câmeras.

<Figure src="/images/zabbix/dvr_intelbras_dashboard.jpeg" alt="Dashboard do Zabbix com métricas do DVR Intelbras" caption="Exemplo de dashboard criado para o DVR." />

Para montar o seu: **Dashboards → Criar dashboard** e adicione widgets (gráficos, problemas, mapa de hosts).

## Troubleshooting

```bash
# Logs dos containers
docker compose logs -f zabbix-server

# Recriar containers SEM apagar dados
docker compose up -d --force-recreate

# ⚠ Recriar do zero: o -v APAGA os volumes (banco de dados incluso)
docker compose down -v && docker compose up -d
```

### Firewall e SNMP: a direção importa

A versão anterior deste artigo sugeria liberar a porta 161/UDP **no servidor Zabbix** — isso é desnecessário e amplia a superfície de ataque. Quem escuta na 161 é o **DVR**; o servidor apenas inicia a consulta (e recebe a resposta pela mesma "conexão" UDP rastreada pelo firewall).

- No **DVR** (ou firewall da VLAN): permita 161/UDP **somente** a partir do IP do servidor Zabbix.
- No **servidor Zabbix**: garanta apenas que o tráfego de **saída** para o DVR na 161/UDP não esteja bloqueado.
- Traps SNMP (porta 162/UDP, do dispositivo para o servidor) só precisam de liberação de entrada se você configurar o recebimento de traps.

### Zabbix não coleta dados

1. O template está vinculado e a interface SNMP está correta?
2. A versão SNMP e as credenciais (community ou usuário v3) batem com o DVR?
3. O `snmpwalk` funciona **a partir do container** do servidor? Teste com `docker compose exec zabbix-server snmpwalk ...` (se a imagem tiver as ferramentas) ou de outro host na mesma rede.
