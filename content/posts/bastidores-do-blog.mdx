Este blog nasceu como um template simples. A nova versão foi reconstruída com três objetivos: **ler** (conteúdo revisado e referenciado), **executar** (laboratórios interativos no navegador) e **confiar** (segurança e testes automatizados). Este artigo documenta as decisões.

- **Next.js 16 + React 19 (Server Components)**: a maior parte da página é renderizada no build e não envia JavaScript ao navegador<Cite id="nextjs-docs,react-docs" />.
- **TypeScript estrito** em todo o código.
- **MDX** para escrever artigos que misturam prosa e componentes<Cite id="mdx-docs" />.
- **Tailwind CSS 4** com tokens de design em variáveis CSS (tema claro/escuro sem "flash").

## Conteúdo confiável: esquema e referências

Cada artigo declara suas referências no frontmatter, e o esquema **exige pelo menos uma**. As citações no texto usam um componente que aponta para a lista final:

```markdown
O umask usa E lógico com o complemento da máscara<Cite id="man-umask" />.
```

Um `id` inexistente interrompe o build — não há citação órfã. A lista é formatada segundo a ABNT NBR 6023<Cite id="abnt-6023" />, e cada artigo oferece um bloco "Como citar" pronto para copiar.

## Laboratórios: executando código com segurança

Executar código digitado pelo leitor exige isolamento. Os playgrounds usam **Web Workers** — threads separadas, sem acesso ao DOM, aos cookies ou ao armazenamento da página<Cite id="mdn-workers" />. Experimente:

```javascript runnable title="Seu código roda em um Web Worker isolado"
const inicio = performance.now();
const primos = [];
for (let n = 2; primos.length < 10; n++) {
  if (primos.every((p) => n % p !== 0)) primos.push(n);
}
console.log("Primeiros 10 primos:", primos);
console.log(`Calculado em ${(performance.now() - inicio).toFixed(3)} ms`);

// Tente acessar a rede: a CSP do worker bloqueia.
try {
  await fetch("https://example.com");
} catch (erro) {
  console.error("fetch bloqueado:", erro.message);
}
```

As camadas de defesa:

1. **CSP própria por worker**: o executor de JavaScript tem `default-src 'none'; script-src 'unsafe-eval'` — pode avaliar o código, mas não faz nenhuma requisição de rede.
2. **Timeout**: se o código não terminar em 5 s (por exemplo, um `while (true)`), o worker é encerrado com `terminate()`.
3. **Limite de saída**: impressões descontroladas são truncadas.
4. **Python sob demanda**: o runtime Pyodide (CPython em WebAssembly) só é baixado quando você executa Python, a partir de uma única origem com versão fixada<Cite id="pyodide" />.

Os demais laboratórios (simulador de Kubernetes, calculadoras ópticas, permissões Unix) são funções puras em TypeScript com testes unitários — a interface apenas desenha o estado.

## Loja 3D

A loja usa **three.js**, carregado somente na página do produto<Cite id="threejs" />. O visualizador lê STL (o formato de impressão 3D, com eixo Z para cima), centraliza o modelo sobre uma "mesa de impressão", calcula as dimensões em milímetros e permite trocar a cor do filamento, ver a malha e entrar em tela cheia. A renderização pausa quando o visualizador sai da tela. O pagamento é feito em plataforma externa: **nenhum dado de pagamento passa por este site**.

## Segurança

| Controle | Implementação |
| --- | --- |
| Content Security Policy | `default-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, iframes só do Giscus<Cite id="mdn-csp,owasp-csp" /> |
| Transporte | HSTS com `includeSubDomains` e `preload` |
| Isolamento | `Cross-Origin-Opener-Policy: same-origin`, `X-Content-Type-Options: nosniff` |
| Privacidade | Fontes auto-hospedadas, comentários carregados só ao rolar até eles, `Referrer-Policy` restritiva, `Permissions-Policy` negando câmera, microfone e geolocalização |
| JSON-LD | Serialização com escape de `<` para impedir quebra do `<script>` |
| Dependências | Auditoria no CI e atualização automatizada |

<Callout type="info" title="Uma concessão consciente">
A CSP permite `'unsafe-inline'` para scripts. Uma CSP com *nonce* exigiria renderizar cada página por requisição, perdendo o cache em CDN de um site estático. Como todo o conteúdo é versionado e revisado, e nenhum HTML de terceiros é injetado na página, o risco residual é baixo — e as demais diretivas continuam restritivas.
</Callout>

## Acessibilidade e desempenho

- Navegação completa por teclado, link "pular para o conteúdo", foco visível e componentes com papéis ARIA (abas, busca, quizzes)<Cite id="wcag22" />.
- `prefers-reduced-motion` respeitado em todas as animações.
- Barra de progresso de leitura feita apenas com CSS (*scroll-driven animations*).
- Imagens locais com dimensões calculadas no build (sem *layout shift*) e formatos AVIF/WebP — boas práticas alinhadas aos Core Web Vitals<Cite id="web-vitals" />.
- Busca instantânea com **Ctrl+K** (ou `/`), sem servidor.

## Testes

- **Unitários (Vitest)**: conteúdo (esquema, citações, compilação de todos os artigos), formatação ABNT, cálculos ópticos, permissões, simulador de Kubernetes, CSP e utilitários.
- **De componentes (Testing Library)**: interações dos laboratórios e do tema.
- **Ponta a ponta (Playwright)**: um "usuário" navega pela home, filtra artigos, usa a busca, troca o tema, executa código, interage com os simuladores, abre a loja 3D, verifica cabeçalhos de segurança, links e acessibilidade com axe<Cite id="playwright" />.
