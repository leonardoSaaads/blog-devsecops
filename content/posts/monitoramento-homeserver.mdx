## Um homeserver 😈

Primeiro de tudo: não tem escapatória. Mesmo buscando autonomia total sobre seus dados, você continua dependendo de uma malha — muitas vezes invisível — de datacenters espalhados pelo mundo.

Isso tem dois lados. O ruim: seus dados ficam em "bancos virtuais" de terceiros, sujeitos a vazamentos e a usos que beneficiam mais a empresa do que você. O bom: esses datacenters são fortalezas preparadas para falhas de energia, desastres naturais e ataques. Um homeserver não substitui a nuvem — ele devolve a você **controle** sobre parte da sua infraestrutura.

## O que é um homeserver?

É literalmente um servidor doméstico: um computador que funciona como hub para armazenamento, backup, automação residencial e acesso remoto.

- **Armazenamento e backup**: aquelas fotos de família de 1839 deixam de depender do plano de R$ 29,90 da nuvem.
- **Casa inteligente**: peça central da automação residencial.
- **Acesso remoto**: de qualquer lugar (veja o [artigo sobre Cloudflare Tunnel](/blog/cloudflared-tunnel-tutorail)).
- **Hospedagem**: sites, bancos de dados e serviços rodando 24/7.

Para começar, um PC antigo ou mini PC com Linux resolve. Sistemas como o ZimaOS facilitam a instalação de aplicativos por meio de uma loja integrada.

## Por que monitorar?

Um servidor sem monitoramento é um carro sem painel: você só descobre o problema quando ele já aconteceu. O disco encheu e o banco parou; a CPU está em 100% há três dias; a memória esgotou e o kernel começou a matar processos (<Term def="Out-Of-Memory killer: mecanismo do kernel que, sem memória disponível, escolhe e encerra processos para manter o sistema de pé.">OOM killer</Term>).

Dois métodos ajudam a decidir **o que** observar:

## Estrutura do projeto

```text
homeserver-stack/
├── .gitignore
├── compose.yaml
├── grafana/
│   ├── dashboards/node-exporter.json
│   └── provisioning/
│       ├── dashboards/dashboard.yml
│       └── datasources/datasource.yml
├── prometheus/
│   ├── prometheus.yml
│   └── rules/
└── secrets/                    # nunca versionar
    ├── cloudflare_token.txt
    └── grafana_password.txt
```

Isso é **infraestrutura como código**: tudo definido em arquivos versionáveis e replicáveis. Se o servidor queimar, você sobe tudo de novo em minutos.

### Crie o .gitignore primeiro

```bash title="homeserver-stack/.gitignore"
secrets/
*.token
*.key
*.log
```

### Gerando os segredos

```bash
mkdir -p secrets
openssl rand -base64 32 > secrets/grafana_password.txt
# Token do túnel (veja o artigo sobre Cloudflare Tunnel); read -s não ecoa nem grava no histórico
read -rs TOKEN && printf '%s' "$TOKEN" > secrets/cloudflare_token.txt && unset TOKEN

chmod 700 secrets            # só o seu usuário atravessa a pasta
chmod 644 secrets/*.txt      # legível pelos usuários não-root dos containers
```

<Callout type="info" title="Por que 700 na pasta e 644 nos arquivos?">
Os *secrets* do Compose (fora do Swarm) são montados como arquivos dentro do container, com as mesmas permissões do host<Cite id="compose-secrets" />. Os containers rodam com usuários não-root (UID 472 no Grafana, 65532 no cloudflared), que precisam ler o arquivo. A pasta `700` impede que outros usuários **do host** cheguem até ele.
</Callout>

## O Docker Compose

```yaml title="homeserver-stack/compose.yaml"
x-logging: &logging
  driver: local          # rotação embutida no Docker; dispensa contêiner de logrotate
  options:
    max-size: "10m"
    max-file: "3"

x-hardening: &hardening
  restart: unless-stopped
  security_opt: ["no-new-privileges:true"]
  cap_drop: [ALL]
  logging: *logging

networks:
  monitoring: {}          # Grafana, Prometheus e cloudflared
  metrics:
    internal: true        # Node Exporter só fala com o Prometheus

volumes:
  prometheus_data: {}
  grafana_data: {}

secrets:
  cloudflare_token:
    file: ./secrets/cloudflare_token.txt
  grafana_admin_password:
    file: ./secrets/grafana_password.txt

services:
  node-exporter:
    <<: *hardening
    image: prom/node-exporter:v1.12.1
    command:
      - "--path.procfs=/host/proc"
      - "--path.sysfs=/host/sys"
      - "--path.rootfs=/rootfs"
      - "--collector.filesystem.mount-points-exclude=^/(sys|proc|dev|host|etc)($$|/)"
    volumes:
      - /proc:/host/proc:ro
      - /sys:/host/sys:ro
      - /:/rootfs:ro,rslave
    networks: [metrics]
    read_only: true
    deploy:
      resources:
        limits: { cpus: "0.5", memory: 128M }
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://localhost:9100/metrics"]
      interval: 30s
      timeout: 5s
      retries: 3

  prometheus:
    <<: *hardening
    image: prom/prometheus:v3.15.0
    command:
      - "--config.file=/etc/prometheus/prometheus.yml"
      - "--storage.tsdb.path=/prometheus"
      - "--storage.tsdb.retention.time=15d"
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml:ro
      - ./prometheus/rules:/etc/prometheus/rules:ro
      - prometheus_data:/prometheus
    ports:
      - "127.0.0.1:9090:9090"
    networks: [monitoring, metrics]
    user: "65534:65534"
    read_only: true
    tmpfs: [/tmp]
    depends_on:
      node-exporter: { condition: service_healthy }
    deploy:
      resources:
        limits: { cpus: "1.0", memory: 1G }
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://localhost:9090/-/healthy"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 30s

  grafana:
    <<: *hardening
    image: grafana/grafana:13.2.4
    environment:
      GF_SECURITY_ADMIN_USER: admin
      GF_SECURITY_ADMIN_PASSWORD__FILE: /run/secrets/grafana_admin_password
      GF_SERVER_ROOT_URL: https://grafana.seudominio.com
      GF_USERS_ALLOW_SIGN_UP: "false"
      GF_AUTH_ANONYMOUS_ENABLED: "false"
      GF_SECURITY_DISABLE_GRAVATAR: "true"
      GF_SNAPSHOTS_EXTERNAL_ENABLED: "false"
      GF_ANALYTICS_REPORTING_ENABLED: "false"
    secrets: [grafana_admin_password]
    volumes:
      - grafana_data:/var/lib/grafana
      - ./grafana/provisioning:/etc/grafana/provisioning:ro
      - ./grafana/dashboards:/var/lib/grafana/dashboards:ro
    ports:
      - "127.0.0.1:3000:3000"
    networks: [monitoring]
    user: "472"
    depends_on:
      prometheus: { condition: service_healthy }
    deploy:
      resources:
        limits: { cpus: "1.0", memory: 512M }
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://localhost:3000/api/health"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 30s

  cloudflared:
    <<: *hardening
    image: cloudflare/cloudflared:2026.10.0
    # --metrics expõe /metrics e /ready para o Prometheus monitorar o túnel
    command: tunnel --no-autoupdate --metrics 0.0.0.0:2000 run
    environment:
      TUNNEL_TOKEN_FILE: /run/secrets/cloudflare_token
    secrets: [cloudflare_token]
    networks: [monitoring]
    read_only: true
    tmpfs: [/tmp]
    depends_on:
      grafana: { condition: service_healthy }
    deploy:
      resources:
        limits: { cpus: "0.5", memory: 128M }
```

## Destrinchando o Compose 🔬

**Redes isoladas.** Duas redes aplicam o princípio do menor privilégio: o Node Exporter fica numa rede `internal` (sem saída para a internet) acessível apenas pelo Prometheus. Se o Grafana for comprometido, ele não alcança o exporter diretamente.

**Portas só em localhost.** `127.0.0.1:3000:3000` deixa o Grafana acessível apenas a partir do próprio servidor. O Node Exporter nem publica porta: o Prometheus o alcança pela rede interna.

**Healthchecks.** O Docker verifica periodicamente se cada serviço responde, e o `depends_on` com `service_healthy` sobe a stack na ordem certa. O `cloudflared` não tem healthcheck interno porque sua imagem é *distroless* (sem shell nem `wget`); em vez disso, ele expõe `/ready` e `/metrics` com a flag `--metrics`<Cite id="cf-run-parameters" />, e o próprio Prometheus passa a monitorá-lo.

**Senha do Grafana via arquivo.** Qualquer opção de configuração do Grafana aceita o sufixo `__FILE` para ler o valor de um arquivo — por isso usamos `GF_SECURITY_ADMIN_PASSWORD__FILE` apontando para o *secret*, em vez da senha em texto puro no Compose<Cite id="grafana-docker" />.

**Limites de recursos.** Evitam que um container descontrolado derrube a máquina inteira.

**Hardening.** `no-new-privileges`, `cap_drop: [ALL]`, usuários não-root e sistemas de arquivos *read-only* reduzem drasticamente o que um invasor consegue fazer dentro de um container.

**Logs com rotação nativa.** A versão anterior usava a imagem `blacklabelops/logrotate`, sem manutenção há anos e com acesso de escrita a `/var/log` do host. O driver `local` do Docker já faz rotação e compressão<Cite id="docker-logging" />.

<Callout type="warning" title="Métricas de rede em rede bridge">
Em uma rede bridge, o Node Exporter enxerga a interface de rede **do próprio container**, e não a do host: os painéis de tráfego mostrarão pouco movimento. Para medir a rede real do servidor, execute o exporter com `network_mode: host` e `pid: host` — e, nesse caso, bloqueie a porta 9100 no firewall do host, já que ela deixa de ser isolada pelo Docker<Cite id="node-exporter" />.
</Callout>

## Configurando o Prometheus

```yaml title="homeserver-stack/prometheus/prometheus.yml"
global:
  scrape_interval: 15s
  evaluation_interval: 15s
  external_labels:
    environment: "homelab"

scrape_configs:
  - job_name: "prometheus"
    static_configs:
      - targets: ["localhost:9090"]

  - job_name: "node"
    static_configs:
      - targets: ["node-exporter:9100"]
        labels:
          hostname: "meu-homeserver"

  # Monitore o monitoramento: estado do túnel
  - job_name: "cloudflared"
    static_configs:
      - targets: ["cloudflared:2000"]
```

### De contadores a taxas: rate() e increase()

A maioria das métricas do Node Exporter é de contadores: `node_cpu_seconds_total` e `node_network_receive_bytes_total` só crescem desde a inicialização do host<Cite id="node-exporter" />.

<Definition term="Contador (counter)">
Métrica cumulativa que só aumenta — ou volta a zero quando o processo reinicia. O valor absoluto quase nunca interessa: o que importa é a variação por unidade de tempo<Cite id="prom-metric-types" />.
</Definition>

A função `rate(x[5m])` calcula a taxa média por segundo dentro da janela, corrigindo os reinícios do contador e extrapolando até as bordas; `increase()` é a mesma conta multiplicada pela duração da janela<Cite id="prom-functions" />. Por isso não se usa `delta()` em contadores: no reinício, a diferença fica negativa.<Sidenote>No Prometheus 3, as janelas são abertas à esquerda: uma amostra exatamente no início da janela é excluída<Cite id="prom-migration" />.</Sidenote>

<RateExplainer />

Na prática, use janelas de pelo menos quatro intervalos de scrape — com scrape de 15 s, `[1m]` ou mais — para que sempre haja amostras suficientes, mesmo que uma coleta falhe.

## Configurando o Grafana como código

O Grafana lê arquivos de *provisioning* na inicialização: datasources e dashboards aparecem sem nenhum clique<Cite id="grafana-provisioning" />. O `uid` fixo do datasource permite que os dashboards o referenciem de forma estável.

```yaml title="grafana/provisioning/datasources/datasource.yml"
apiVersion: 1
datasources:
  - name: Prometheus
    uid: prometheus
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    isDefault: true
    editable: false
    jsonData:
      timeInterval: 15s
```

```yaml title="grafana/provisioning/dashboards/dashboard.yml"
apiVersion: 1
providers:
  - name: homeserver
    folder: Homeserver
    type: file
    disableDeletion: true
    allowUiUpdates: false
    options:
      path: /var/lib/grafana/dashboards
```

## Subindo tudo 🚀

```bash
docker compose config --quiet && echo "ok"
docker compose up -d
docker compose ps                               # todos "healthy"
curl -s http://127.0.0.1:9090/-/healthy
curl -s http://127.0.0.1:3000/api/health
```

Acesse `http://127.0.0.1:3000` (usuário `admin`, senha em `secrets/grafana_password.txt`). Remotamente, publique `grafana:3000` no túnel — **com Cloudflare Access na frente** — e acesse `https://grafana.seudominio.com`.

Em **Status → Target health** no Prometheus, os três jobs (`prometheus`, `node`, `cloudflared`) devem estar `UP`.

## Comandos úteis

```bash
docker compose logs -f prometheus     # logs de um serviço

```

## Troubleshooting

```bash
# Grafana não conecta no Prometheus
docker compose exec grafana wget -qO- http://prometheus:9090/-/healthy

# Targets do Prometheus
curl -s http://127.0.0.1:9090/api/v1/targets | head -c 600

# Container reiniciando: veja o motivo
docker inspect --format '{{json .State.Health}}' prometheus
```
