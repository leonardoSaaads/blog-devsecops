# Leonardo Saads — Engineering, Telecommunications and Software

A technical blog designed like an **academic publication** — abstract, numbered figures and equations, margin notes and IEEE-style references — with **interactive figures right in the text**: simulators, calculators and a 3D optical fiber model. Every article gets an illustration generated by code from its topic.

**Production:** [blog.leonardosaads.com.br](https://blog.leonardosaads.com.br)

## Overview

| Feature           | Description                                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Reviewed articles | Schema-validated MDX (Zod); the build fails on invalid frontmatter                                                                    |
| IEEE references   | Every article requires references; `<Cite id>` produces numbered citations and an IEEE-style reference list                           |
| Editorial design  | Abstract, keywords and key takeaways per article; numbered figures, listings, definitions and equations; margin notes; glossary       |
| In-text figures   | 3D optical fiber, DWDM grid, fiber bands, OSNR, Q/BER, constellations, OTN; Unix permissions, signals/PID 1 and the filesystem tree   |
| Generative art    | Deterministic SVG per article (seed = slug) on the cover, the cards and the Open Graph image                                          |
| Reading           | Scroll-spy table of contents, CSS reading progress, Ctrl+K search, area/tag filters, light/dark/system theme, "Cite this article"     |
| SEO               | Metadata, generated Open Graph images, JSON-LD (`BlogPosting` with `abstract`, `articleSection` and `citation`), sitemap, robots, RSS |
| Quality           | Strict TypeScript, ESLint, Vitest, Playwright + axe (WCAG 2.2 AA) and CI on GitHub Actions                                            |

## Stack

- **Next.js 16** (App Router, Turbopack, static export) + **React 19**
- **TypeScript 6** (strict; the native TypeScript 7 does not yet expose the API `typescript-eslint` needs)
- **Tailwind CSS 4** + `@tailwindcss/typography`
- **MDX 3** (`@mdx-js/mdx`) with remark-gfm, remark-math/rehype-katex, rehype-slug and Shiki
- **Zod 4** (frontmatter validation)
- **three.js** (3D fiber model, loaded on demand)
- **Source Serif 4** (reading) and **Geist** (interface), self-hosted
- **Vitest 5** + Testing Library · **Playwright** + **axe-core**
- **Giscus** (comments via GitHub Discussions, loaded on demand)

## Requirements

- Node.js **22.18+** — runs TypeScript natively in the image script (CI and Cloudflare use Node 24 LTS from `.nvmrc`)
- npm 10+

| `npm run dev`                        | Development server                                      |
| `npm run images`                     | Generates WebP variants in `public/_img/` (incremental) |

| `npm test` / `npm run test:coverage` | Unit and component tests (Vitest)                       |

## Writing articles

Create `content/posts/my-article.mdx` (the file name is the slug):

```mdx
---
title: "Article title"
description: "A 20–300 character summary shown on cards and in search results."
date: "2026-10-13"
updated: "2026-10-20" # optional
tags: ["kubernetes", "devsecops"] # lowercase kebab-case
category: infrastructure # telecommunications | infrastructure | security | software
art: lattice # spectrum | lattice | bits | network | ridgeline | radar | flamegraph | circuit | eye
abstract: "A 120–900 character academic abstract, shown at the top of the article."
keyPoints: # 3 to 4 main takeaways
  - "The controller compares the desired state with the current one."
  - "A Service provides a stable address."
  - "Secrets are only base64-encoded."
references:
  - id: k8s-docs
    type: web # book | article | conference | standard | report | web | software
    authors: ["The Kubernetes Authors"] # people: "Family, Given"
    title: "Deployments"
    container: "Kubernetes Documentation"
    year: 2026
    url: "https://kubernetes.io/docs/concepts/workloads/controllers/deployment/"
    accessed: "2026-10-13"
---

A Deployment keeps the desired number of replicas<Cite id="k8s-docs" />.

<Definition term="Reconciliation">
  The loop in which the controller moves the current state toward the desired one.
</Definition>

Text with a note<Sidenote>A comment in the margin.</Sidenote> and a <Term def="Definition in a popover.">term</Term>.

<CardGrid>
  <Card title="Pod" icon="box">
    The smallest deployable unit.
  </Card>
  <Card title="Service" icon="network" tone="signal">
    A stable address.
  </Card>
</CardGrid>
```

Rules checked automatically (build and tests):

- valid frontmatter with **at least one reference**;
- every `<Cite id>` points to an existing reference and every reference is cited;
- local images exist; internal `/blog/...` links point to existing articles;
- every article compiles and renders.

Text components: `Cite`, `Callout`, `Figure`, `Video`, `Tabs`/`Tab`, `Quiz`, `Sidenote`, `Term`, `Definition`, `PullQuote`, `Card`/`CardGrid` (icons from a closed list) and `FlowDiagram`. Formulas: `$$ … $$` (KaTeX, numbered automatically).

## Editorial design

- **Cover** with the article art, area, serif title, standfirst and author; then the **Abstract** with keywords and metadata, and the **Key takeaways** as cards.
- **Automatic numbering** via CSS counters: `Figure n.`, `Definition n.` and equations `(n)`, in order of appearance — no JavaScript.
- **Margin notes** (`<Sidenote>`): float in the right column from 80rem up; inline on smaller screens.
- **Inline glossary** (`<Term def>`): opens on hover, focus or tap and closes with Esc (WCAG 1.4.13).
- Three-column layout on wide screens: table of contents on the left, text (≈42rem) and a margin for notes; interactive figures extend into the margin.

## Interactive figures

Each figure is a numbered MDX component (`InteractiveFigure`) placed in the flow of the text. The logic lives in `src/lib/simulations/` as pure, tested functions; the components in `src/components/figures/` only draw the state.

| Figure                                                                                                                        | Article |
| ----------------------------------------------------------------------------------------------------------------------------- | ------- |
| `Fiber3D`, `DwdmGridCalculator`, `FiberBandsChart`, `OsnrCalculator`, `QBerCalculator`, `ConstellationViewer`, `OtnHierarchy` | DWDM    |
| `PermissionLab`, `SignalSimulator`, `FilesystemExplorer`                                                                      | Linux   |

The 3D model imports three.js dynamically when the figure scrolls into view, pauses off screen, does not capture page zoom and offers an SVG cross-section as a no-WebGL fallback.

## Generative art

`src/lib/art/motifs.ts` defines nine topic-related motifs (DWDM spectrum, node lattice, bit matrix, network and tunnels, time series, radar, flame graph, circuit and eye diagram). The seed is the FNV-1a hash of the slug and the PRNG is mulberry32: the same input always produces the same SVG.

- **Static file, not HTML:** the route `src/app/art/[motif]/[file]/route.ts` pre-renders one SVG per artwork in use (`/art/<motif>/<seed>.svg`, cataloged in `src/lib/art/catalog.ts`). Covers and cards use `CoverArt`, an `<img>` with `loading="lazy"` (the article cover uses `fetchpriority="high"`). Previously the SVGs were inlined in the HTML and the React payload: the home page weighed 1.9 MB and had thousands of nodes to hydrate.
- **Lean SVG:** polylines with relative coordinates, Bézier curves and same-paint shapes merged into a single `<path>` (every file < 70 KB, enforced by a test).
- **Static for performance:** animating elements inside a full-screen SVG forces re-rasterization every frame and, measured without a GPU, kept two CPU cores busy on an idle page; an E2E test ensures the cover has no infinite animations.
- Open Graph images reuse the same SVG as a data URI.

## Performance

Measured by simulating a new visitor (empty cache, 4× CPU slowdown, 4G network) browsing the home page, an article with the 3D figure, search and the listings:

| Metric                                | Before                                             | After        |
| ------------------------------------- | -------------------------------------------------- | ------------ |
| Home HTML (transferred)               | 348 KB                                             | 19 KB        |
| Route prefetch (RSC data) per session | 2.85 MB                                            | 0.67 MB      |
| DOM nodes on the home page            | 2,767                                              | 476          |
| Fonts preloaded on every page         | 4 (≈ 393 KB)                                       | 3 (≈ 173 KB) |
| Console warnings/errors               | Deprecated API (`THREE.Clock`), unused CSS preload | none         |

**Images:** a static export has no Next image optimizer; `scripts/optimize-images.mts` (sharp) generates WebP at 9 widths for every PNG/JPEG in `public/`, and the loader in `src/lib/images/` points `srcset` at them. A typical screenshot drops from hundreds of KB to tens of KB (e.g., 976 KB → 34 KB); the image marked as LCP uses `preload`.

Other measures: each interactive figure's code loads only on the articles that use it (`next/dynamic`), Giscus downloads only when the reader reaches the comments, three.js only when the fiber scrolls into view, and the KaTeX CSS is global (avoids a wasted preload during prefetch).

## Security

- Restrictive **CSP** (`default-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, `worker-src 'none'`); iframes only from Giscus. `script-src` allows `'unsafe-inline'` because the site is static (nonces would require per-request rendering).
- **HSTS** with preload, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, `COOP`, no `X-Powered-By`.
- JSON-LD serialized with escaping; slugs resolved only from the loaded list (no path traversal); reference URLs must be HTTPS.
- Self-hosted fonts; comments and three.js loaded on demand; no external cover images.
- Production dependency audit in CI. Dependabot opens a single semiannual PR (npm + GitHub Actions); security alerts stay immediate. Exceptions documented in `.github/dependabot.yml`: TypeScript 7 (no typescript-eslint support yet) and `@types/node` majors (they track `.nvmrc`).
- Vulnerability reports: see [SECURITY.md](SECURITY.md).

## Deployment

The site is fully static: `next build` generates `out/` (`output: "export"`) and **Cloudflare** serves it as [Workers Static Assets](https://developers.cloudflare.com/workers/static-assets/), configured in `wrangler.jsonc`. No code runs per request — there is no server, image optimizer or disk access in production.

Project settings under **Workers & Pages → Settings → Build**:

| Field          | Value                                                |
| -------------- | ---------------------------------------------------- |
| Build command  | `npm run build`                                      |
| Deploy command | `npx wrangler deploy` (uses the lockfile's wrangler) |
| Root directory | `/`                                                  |
| Build variable | `NEXT_PUBLIC_SITE_URL=https://your-domain`           |

Headers and redirects, which Next would apply on a server, become the `out/_headers` and `out/_redirects` files, generated at build time from `src/lib/security/headers.ts` and `src/lib/hosting/` (the same sources `next dev` uses). Cloudflare applies them and does not serve them publicly. `npm run build && npm start` reproduces production locally via `wrangler dev`; the E2E tests run against it.

> Do not use OpenNext (`@opennextjs/cloudflare`): it runs Next inside a Worker, where `content/posts` does not exist on disk, and it exposes unnecessary server routes.

Old links keep working with 308 redirects: the Portuguese slugs and tags from before the English translation (e.g., `/blog/comandos-linux` → `/blog/linux-fundamentals`, `/tags/seguranca` → `/tags/security`) and uppercase tags (`/tags/UPPERCASE` → `/tags/uppercase`).
